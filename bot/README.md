# Управление меню в Telegram

Бот работает в личном чате и принимает команды только от Telegram ID из списка администраторов. Python 3.12; Pillow обрабатывает загруженные картинки. В Actions зависимость устанавливается автоматически.

## Первый запуск

1. Создайте бота через официальный **@BotFather** командой `/newbot` и получите токен.
2. Откройте [Settings → Secrets and variables → Actions](https://github.com/retrocoffee/coffee/settings/secrets/actions) и добавьте два **Repository secrets**:
   - `TELEGRAM_BOT_TOKEN` — токен от BotFather.
   - `TELEGRAM_ADMIN_IDS` — ваш числовой Telegram user ID; несколько ID разделяются запятыми, например `123456789,987654321`. Это не @username и не номер телефона. ID можно узнать из поля `from.id` Telegram Bot API `getUpdates`, отправив своему боту сообщение до первого запуска; не публикуйте URL с токеном и ответ API. Также можно воспользоваться доверенным ботом определения ID.
3. Откройте [Actions → Telegram menu admin](https://github.com/retrocoffee/coffee/actions/workflows/telegram-bot.yml), нажмите **Run workflow** для `main`.
4. Откройте личный чат с созданным ботом и отправьте `/start`.

Секреты не передавайте в чат с ассистентом и не добавляйте в код. При отсутствии секретов workflow завершится без запуска бота и выведет инструкцию в Summary. Репозиторию нужны разрешения для `GITHUB_TOKEN`: `contents: write`, `actions: write` (указаны в workflow); политика организации не должна их запрещать. Если ветка `main` защищена от прямой записи Actions, сохранение будет отклонено; нельзя автоматически обходить защиту.

## Управление

- Внизу чата доступна постоянная reply-клавиатура: **Главное меню**, **Массовая загрузка**, **История меню**, **Отмена**. Кнопки работают и во время ввода: переход или отмена сбрасывает несохранённый черновик. Если клавиатура свёрнута, откройте её значком возле поля ввода или отправьте `/start`.
- Главный экран: разделы, создание раздела, история, повторный запуск публикации.
- Раздел: переименование, скрытие/показ, удаление с подтверждением, группы позиций.
- Группа: список позиций, добавление позиции, подписи объёмов. Группы сохраняют существующую табличную раскладку, включая добавки и разные объёмы.
- Позиция: изменение цен, переименование, описание, картинка, удаление с подтверждением.
- Для добавления позиции отправьте название первой строкой, цены через `;` второй, затем необязательное описание. Число цен должно соответствовать объёмам группы.
- Цены: `220; 260`, также допустимы `бесплатно` и `—` (позиция недоступна для данного объёма).
- Новый раздел создаётся с одной группой без подписи объёма и одной ценой. В пустой группе можно настроить несколько объёмов. В заполненной группе подписи редактируются без изменения числа колонок; для другого набора объёмов создайте новую группу.
- Каждая правка сначала показывается как черновик; кнопка **Сохранить** записывает её в GitHub. **Отмена** и `/cancel` отменяют ввод. `/start` обновляет данные.
- В истории доступны даты, действия, просмотр позиций и цен, восстановление версии с подтверждением. Восстановление создаёт новую запись; предыдущая история сохраняется. История начинается с внедрения этого редактора, а не с прежних HTML-версий.

Если два администратора редактируют одну версию, после сохранения первого второй получит предложение обновить меню. Нельзя затереть свежие данные старым черновиком. Устаревшие inline-кнопки недействительны; после перезапуска используется `/start`. Незавершённые черновики при перезапуске не сохраняются.

## Картинка позиции

Откройте **раздел → группа → позиция → Картинка → Добавить картинку** (или **Заменить картинку**). Отправьте фото либо JPG/PNG/WebP-файл, затем нажмите **Сохранить**. До подтверждения сайт не меняется. **Отмена** сбрасывает загрузку. Для сохранения прозрачного фона отправляйте PNG или WebP как файл, без сжатия Telegram.

Лимит — 5 МБ и 16 мегапикселей; анимация и SVG не принимаются. Бот проверяет фактический формат, исправляет ориентацию, уменьшает картинку до 640×640 и удаляет метаданные (включая EXIF). Маленькие изображения не растягиваются при обработке. На сайте картинка вписывается в одинаковое компактное место слева от текста. Если позиция есть в карусели, её картинка также обновляется там.

**Стандартная иконка** возвращает исходную иконку меню и иллюстрацию карусели. Новые позиции получают иконку автоматически. Картинка и меню сохраняются одним коммитом и восстанавливаются вместе через историю; старые изображения не удаляются. Изменения цен, названий и массовая загрузка CSV сохраняют назначенные картинки. Содержимое картинок публично, как и меню; не загружайте личные или служебные материалы.

## Генерация по описанию

Для новой позиции сначала сохраните название, цены и описание: на экране подтверждения сохранения появится **Картинка новой позиции**. Для любой существующей позиции откройте **раздел → группа → позиция → Картинка → Сгенерировать по описанию**.

1. Введите, что нарисовать (до 1500 символов), или нажмите **Использовать описание позиции**. Пример: «Высокий стакан айс-латте со льдом и молочной пеной».
2. Проверьте описание и нажмите **Сгенерировать**. Только эта кнопка отправляет платный запрос.
3. Бот покажет изображение в чате. **Сохранить** записывает его вместе с меню в GitHub и запускает публикацию. **Ещё вариант** возвращает к подтверждению нового запроса; **Показать картинку** повторно показывает готовый результат без генерации и оплаты.
4. **Отмена** или переход к другому экрану сбрасывает черновик. Прежняя картинка позиции остаётся до сохранения новой. Предпросмотр удаляется при переходе, включая переход после перезапуска бота.

Иллюстрации создаются в стиле сайта: чёрно-белый рисунок, прозрачный фон, без надписей, цен и рамок. Обработка, хранение, карусель и восстановление работают так же, как для загруженных вручную картинок. Описание для генерации не заменяет описание позиции на сайте.

### Подключение OpenAI

В [Settings → Secrets and variables → Actions](https://github.com/retrocoffee/coffee/settings/secrets/actions) добавьте **Repository secret `OPENAI_API_KEY`** с ключом вашего OpenAI API-проекта. Нужны доступ к Images API, действующий баланс и разрешённые лимиты проекта. При необходимости OpenAI может потребовать верификацию организации. Ключ не отправляйте боту, не добавляйте в репозиторий или публичные Variables.

После добавления или смены секрета запустите **Actions → Telegram menu admin → Run workflow**, затем отправьте `/start`. Активный процесс получает секреты только при запуске. API оплачивается отдельно от ChatGPT и GitHub Actions; стоимость и квоты зависят от модели и проекта OpenAI. Бот отправляет провайдеру только название позиции, описание рисунка и указания по стилю; Telegram ID, цены, токен бота и остальные позиции не передаются.

По умолчанию используется `gpt-image-1-mini`, один вариант 1024×1024 с качеством `low`, затем результат уменьшается до 640×640. Модель можно изменить через Repository variable **`OPENAI_IMAGE_MODEL`**, например на `gpt-image-1.5`, если она доступна проекту и поддерживает GPT Image Images API с прозрачным WebP. [Параметры Images API в официальном SDK](https://github.com/openai/openai-python/blob/main/src/openai/types/image_generate_params.py).

Без ключа остальные функции бота, включая загрузку картинок вручную, продолжают работать; кнопка генерации показывает инструкцию подключения. Генерация идёт в отдельном потоке, поэтому навигация и редактирование меню доступны во время ожидания. Одновременно выполняется один запрос на весь бот: повторные нажатия и другие администраторы не создают очередь платных запросов. После ошибки, лимита или таймаута автоматического повтора нет.

Отмена скрывает результат и запрещает его сохранение, но не отменяет уже отправленный запрос у провайдера: он может быть оплачен. При плановом перезапуске Actions незавершённая генерация и несохранённые картинки теряются. После таймаута проверьте использование API перед повторным запуском. Не выполняйте массовую генерацию без контроля расходов проекта.

## Массовая загрузка CSV

На главном экране нажмите **Массовая загрузка** для всего меню или откройте группу и нажмите **Массовая загрузка группы**. Выберите режим:

- **Только цены** — меняет цены существующих позиций; названия и описания сохраняются.
- **Позиции и цены** — добавляет позиции и обновляет названия, цены и описания существующих.

Нажмите **Скачать CSV-шаблон**. Бот отправит UTF-8 CSV с текущими строками, которые можно редактировать в Excel, LibreOffice или текстовом редакторе. Для пустых групп добавляются строки только с названием раздела и группы: заполните остальные поля, чтобы добавить позицию. Незаполненные строки пропускаются.

Поля шаблона:

| Поле | Что указать |
| --- | --- |
| `раздел` | Точное название существующего раздела из шаблона |
| `группа` | Точное название группы из шаблона |
| `id` | ID существующей позиции; для новой оставьте пустым |
| `название` | Название позиции; с заполненным ID можно переименовать |
| `цены` | Цены по порядку объёмов группы, разделённые ` | `, например `220 | 260` |
| `описание` | Новое описание; пустое поле сохраняет прежнее, `-` убирает его |

Пример для группы кофе с двумя объёмами (подставьте названия раздела и группы из своего шаблона):

```csv
раздел;группа;id;название;цены;описание
Кофе;Кофейные напитки;;Новый капучино;220 | 260;На цельном молоке
```

Отправьте боту отредактированный файл `.csv`, `.tsv` или `.txt` либо вставьте текст с заголовком. Основной разделитель CSV — `;`, также поддерживаются табуляция и запятая. Несколько цен находятся внутри одного поля, разделитель — `|`. Дробные цены — `220,50` или `220.50`; для отсутствующего объёма используйте `—`. Текст с `;`, кавычками или переносами строк должен быть оформлен по правилам CSV (табличный редактор делает это автоматически).

Для существующих позиций сохраняйте ID. Без ID бот ищет совпадение по названию внутри группы; если его нет, режим «Позиции и цены» создаёт позицию. Неоднозначные названия требуют ID. При ошибке в любой строке весь файл отклоняется с номером строки; исправьте его и отправьте снова. Строки вне выбранной группы, неизвестные ID, повторения позиций и несовпадение количества цен с объёмами отклоняются. Файл не создаёт разделы и группы: сначала добавьте их через кнопки бота.

Лимит: 512 КБ, 1000 позиций. Перед сохранением показаны количества добавленных/изменённых строк и **Все изменения** с постраничным просмотром. После **Сохранить** вся загрузка попадает в историю одним действием. Пропущенные в файле позиции не удаляются. Действуют прежние проверки доступа и защита от параллельного редактирования.

## Сообщения в чате

Навигация, ввод, предпросмотр и история обновляют одно сообщение бота. После перехода прежний экран заменяется новым. Для нижней reply-клавиатуры используется отдельное служебное сообщение: Telegram не позволяет прикрепить reply- и inline-клавиатуры к одному сообщению. При повторном `/start` служебное сообщение заменяется, если Telegram разрешает его удалить. Если основной экран был удалён и его нельзя отредактировать, бот отправит новый и попробует удалить старый. Отправленный ботом CSV-шаблон удаляется при переходе на следующий экран; скачайте его перед переходом. Сообщения с нажатиями нижних кнопок удаляются после перехода, остальные сообщения пользователя сохраняются.

ID текущего экрана сохраняется в служебном кеше между перезапусками. Старые экраны, созданные прежней версией бота, могут оставаться в чате; при нажатии старой кнопки бот удаляет её сообщение, если Telegram ещё разрешает удаление. Команда `/start` открывает актуальное меню.

## Данные и оформление

`data/menu.json` — единственный источник меню. Бот меняет меню и добавляет загруженные картинки в `public/assets/menu-images/`. Каждый подтверждённый набор изменений хранится отдельным Git-коммитом. Имена и ID администраторов не записываются в историю; содержимое меню и его прежние версии публичны, как и репозиторий.

`python3 scripts/build-menu.py` генерирует содержимое `<main class="menu">` и карусель в `public/index.html`. CSS, логотип, заголовок и поведение раскрытия остаются в своих файлах. При изменениях дизайна сохраняйте `data/menu.json` и запускайте генератор. Ручные изменения позиций в сгенерированном HTML будут заменены данными при следующей сборке.

Сохранение ботом запускает `Publish RetroCoffe` через `workflow_dispatch`: обычный push с `GITHUB_TOKEN` не запускает другие workflows. В ответе бот сообщает о запуске, а не об успешном завершении публикации. Её результат доступен в GitHub Actions. Если запуск не удался, меню уже сохранено — нажмите **Опубликовать повторно**.

## Ограничения GitHub Actions

Actions — система запуска задач, а не постоянно работающий сервер. Workflow запускается по расписанию раз в 4 часа; один процесс опрашивает Telegram около 4 часов 5 минут и завершается. `concurrency` допускает только один процесс бота; следующий запуск по расписанию ожидает завершения предыдущего. Обновление кода бота и ручной запуск отменяют прежний процесс, чтобы запустить актуальную версию. Незавершённый ввод при этом теряется; начните с `/start`. Расписание GitHub может задерживаться или пропускать запуски, поэтому непрерывная доступность не гарантируется. Также применяются квоты Actions; в публичных репозиториях GitHub может отключить расписание после 60 дней отсутствия активности. Для гарантированной постоянной работы нужен отдельный сервер или webhook-сервис.

Последний обработанный Telegram update ID и ID сообщений экранов сохраняются в Actions Cache; токена и меню в этих файлах нет. При потере кеша старые сообщения могут быть прочитаны вновь, но старые inline-кнопки не имеют действительных черновиков и не сохраняют изменения. GitHub-история — основной способ восстановления меню.

Если бот недоступен, проверьте активный workflow и запустите его вручную. Для остановки отключите расписание и отмените активный запуск. Не запускайте второй процесс с тем же токеном: long polling Telegram поддерживает один потребитель. Workflow удаляет прежний webhook этого бота при старте; используйте отдельного бота для меню.

## Проверки

`npm run check` проверяет схему, рендеринг, доступ администратора, черновики, подтверждение удаления, восстановление, конфликт параллельных правок, атомарный CSV-импорт и замену сообщений при навигации, Images API с подменёнными ответами, подтверждение генерации, отмену, параллельные нажатия и удаление предпросмотра. Интеграционная проверка реального Telegram требует настроенных секретов и первого запуска.

Платная генерация не запускается в автоматических тестах. Сквозная проверка с реальным OpenAI требует настроенного `OPENAI_API_KEY` и ручного запроса администратора.
